Run a typed Todo app

This follows the same flow as JavaScript, with schema-derived row types and typed command arguments. Build the local packages using installation, then run node docs/public/run_language.mjs typescript from the checkout. The runner uses the installed TypeScript compiler with strict checking, emits JavaScript, and executes it against the real WASM database. It installs nothing.

1. Define your schema

Import the public package. Keep the schema object: its private metadata carries the column policies. A required string column is string; an optional string column can be absent, or contain string | null. Narrow both null and undefined before using an optional value; bigint and Date policies are described in the JavaScript guide.

2. Supply your backend

The fake transport stands in for your server. Its command handler is separate from the local handler below. A production server authenticates the user, validates arguments, deduplicates commands, and returns authoritative results. The empty pull page keeps this example local.

{{example:typescript:backend}}

3. Open and share one database

Open once in your application service. Memory storage is ephemeral. The app-supplied context is not proof of identity. Entity tables track ordinary edits field by field; command-created rows instead require explicit server-ID mappings.

{{example:typescript:open}}

4. Insert and query

This insert happens outside a command on an entity table. It gets a final entity: ID; the library supplies identity mappings when reconciling entity creates. Fetch returns plain rows inferred from your schema.

5. Observe

The callback runs on a later host turn. Await ready to know registration has completed; dispose the returned function when the view no longer needs it.

{{example:typescript:observe}}

6. Run a command

taskId is inferred as a string. The handler receives a tracked database view; its reads and writes share one admission and commit together. Use that view inside the handler. Calls through the outer owner while a handler is admitted return Busy.

{{example:typescript:command}}

7. Sync and close

This command updates an existing row, so its reconciliation plan needs no new-ID mappings. sync() pushes, receives, reconciles, then pulls. Use startSync() for background scheduling and stop it during application shutdown.

{{example:typescript:sync}}

Both the entity insert and the command are now confirmed by the server. When the view no longer needs the watcher, call the function that observe returned.

Close the database when your application shuts down. The full file does this in a finally block, so it also closes after a failed step.

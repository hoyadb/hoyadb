Application API

Start with the complete JavaScript app. The public browser entry and @hoyadb/client/node open builder-branded schemas with plain values. @hoyadb/client/host retains the tagged advanced API below. A numeric version alone does not change that API.

SurfaceUse
defineSchema, table, column, relationDeclare an immutable application schema. applicationSchema deliberately converts an existing wire schema.
openDatabaseOpen memory with automatic runtime bootstrap. Browser filename storage requires a caller-owned key. Node's default runtime supports memory.
db.query, db.relatedLazy queries with symbolic operators, plain predicates and flat rows; to-one relation getters are lazy queries.
query.observe, observeCountReturn an unsubscribe function immediately; await its ready property for registration. Call it to dispose.
db.table(name)Insert rows or obtain a handle with findById. A handle exposes asynchronous fetch, partial update and remove. Fields named update remain data.
defineCommand, db.commandDefine a reusable named handler, bind it to an explicit owner, then execute plain args. executeWithReceipt also returns the queue key.
observeOutcome, observeStatus, observeProgressSubscribe to plain values with the same immediate unsubscribe/ready lifetime.
configureEntities, reconfigureEntitiesExplicit persistent entity opt-in; unconfigured tables stay local.
preparePush, receiveManually exchange plain envelope/outcome arrays through the real core codec.
pendingReconciliations, reconcileRead persisted kind, created-ID map and outcome. Command mappings remain application-defined. Missing entity-created identity mappings are filled before core validation.
sync, startSync, stopSyncAwait a push/reconcile/pull pass, or start background push plus periodic pull. Awaited errors reject; background failures reach the redacted sink, while Busy pull ticks are skipped.
rollback, cancel, forget, reset, closeUse existing core recovery rules and explicit lifetime cleanup.
db.rawAdvanced tagged owner for operations outside the application convenience API.

All exact signatures are included in the generated declarations. Swift and Kotlin retain their existing native surfaces; the JavaScript convenience names are not invented aliases for those SDKs.

Advanced tagged host reference

SDK reference

This page describes what each public JavaScript host method does. Exact signatures are generated from the declarations in SDK declarations; the source of truth is index.d.ts. Swift, Kotlin, React Native and the C ABI expose the same operations; see their generated pages: Swift, Kotlin, React Native and native. Every method that talks to the core returns a Promise and rejects with an Error carrying a static kind.

Module functions

createRuntime(channel, options)
Wraps a channel to the core, an object with open(input, key) and call(input). Use the optional namespace entropy source when the host has no default.
createWebRuntime(options) (browser entry only)
Starts or reuses the dedicated worker that owns OPFS storage. Pass worker to supply your own.
openDatabase(options)
Creates a Database with the host options and opens it. Equivalent to new Database(runtime, options) followed by open(options).
defineSchema(schema)
Returns an immutable copy of a schema declaration: a version and tables of columns and relations (ToOne, HasMany, ManyToMany).
query(table, source)
Builds a detached Query to pass to db.fetch or Scope.fetch. It has no database, so call fetch and observe on db.query(table) instead.
j
Builders for tagged cells and JSON values: null, boolean, string, reference, integer, timestamp, float, array, object.
copyOwned(value), immutableOwned(value)
Deep-copy a value, or deep-copy and freeze it, so later caller mutation cannot affect the SDK.

Runtime

createMemoryStore(), dropMemoryStore(store)
Create or release a retained memory store whose rows survive owner close and reopen. A store belongs to one runtime and allows one open owner at a time.
decodeJson(body), encodeJson(value)
Parse or produce wire JSON with the core codec, so integers keep their full width.
call, open, namespace, jitter
Low-level channel access, used by Database.

Database lifecycle

open(options)
Opens the engine with the schema and any authored migrations. Store options are capacity, history and the retry delays. If a transport is given, automatic sync starts.
close()
Stops sync, invalidates subscriptions and stale callbacks, and releases the owner.
schema(), protection(), diagnostics()
Return the active schema, the storage protection (encrypted, cipher, version, backup) and bounded, payload-free counters.
owner
The open owner handle, or null when closed.

Reading and writing

query(table), related(table, id, relation)
Build a Query bound to this database. where, whereIn, orderBy and limit refine it; fetch runs it, and observe subscribes to it.
fetch(query)
Runs a query or query data and returns the complete row list, or fails with LimitExceeded.
insert(table, fields), replace(table, id, fields), remove(table, id)
Write one row. replace supplies the whole row; remove resolves to whether a row existed.
batch(writes)
Applies several insert, replace and remove writes atomically and returns the committed changes.
link, unlink
Add or remove a many-to-many association through its join table.

Observation

observe(query, callback, mode, columns), observeData(...)
Subscribe to a query. These two are the same operation. Modes are membership, columns and count. The callback receives the snapshot and later changes in order; a returned Promise is not awaited, and a throw retires the listener.
unsubscribe(handle)
Stops any data, status, outcome or progress subscription.
drain(now), refresh()
Deliver pending events now, or recompute observations. Managed observations do both automatically.
observationStats()
Counts of observation groups, observers and materialized rows.

Commands

execute(definition, args, handler, options)
Runs a named command handler with a Scope and commits its writes once, queuing the command durably. Resolves to its key and handler result. Pass an abort signal in options to cancel before commit.
Scope
The handler's view: args, the captured context, and fetch, insert, replace, remove, batch, link and unlink staged until the handler returns. Rows a command creates need local: IDs.

Queue and sync

startSync(transport, reconcile), stopSync(), sync()
Start or stop automatic push cycles, or run one now. Only the transport's push is used. reconcile receives each pending outcome and returns its plan. A conflicting plan is not retried in the same pass.
preparePush(now, jitter)
Freezes the next eligible writes. Returns their envelopes, the next deadline and whether more remain.
receiveWire(body), receive(key, outcome), receiveEntity(...)
Record the backend's answers: a whole outcome array, or one command or entity outcome. An outcome of null records a receipt without a final result.
requestRedelivery(key, now)
Re-arms an acknowledged command whose final outcome was lost, keeping its frozen bytes.
pendingReconciliations()
Lists outcomes still waiting for the application's decision.
reconcile(key, plan), reconcileGuarded(key, plan, guards)
Confirm an applied or corrected command. The plan's mappings name the server ID of every local ID it created; its writes carry authoritative corrections. Guards give the expected current value of each row written outside the command. A correction that cannot be proven safe fails with RollbackConflict and changes nothing.
rollback(key), cancel(key), forget(key)
Undo a processed rejection, withdraw queued, sent or rejected work, or remove finished history. A cancel inverse conflict records Cancelled and keeps recovery data even though it returns RollbackConflict. Rollback refuses with RollbackConflict if later edits would be overwritten.
queueStatus(), observeStatus(callback), observeOutcome(key, callback)
Inspect queued writes: state, attempts, the next deadline, and awaiting_key when an earlier write to the same row must resolve first. Or subscribe to status or to one command's outcome.

Entity sync

configureEntities(scope, tables), reconfigureEntities(scope, tables)
Opt tables into per-field entity sync, or change that configuration.
patch, entityBatch, entityLink, entityUnlink
Local entity edits that record stamped field changes for push.
pullOnce(transport), syncProgress(), observeProgress(callback)
Apply backend pages until complete, and report bootstrap progress.
setMergeHooks(hooks)
Per-table functions that propose a merged row, or null; the core validates every proposal.
reset(mode)
Restart entity sync, with preserve_recovery (the default) or discard_recovery.

Testing package

openMemoryDatabase(options)
Opens a real memory database for tests. A 32-hex namespace is required, and no key is allowed.
createClock(initial)
A manual clock with set(value).
createFakeTransport({runtime, handlers, entityHandlers, pull})
A backend stand-in that decodes pushed envelopes with the core codec. It calls your handler for each command or entity table, and records every push in pushes.

Background errors

The onBackgroundError option receives {source, kind, token} for failures outside an awaited call. The source is observation, callback, sync, merge or timer, and each fact is reported once per owner. Never included: messages, payloads, keys or rows. In the current JavaScript SDK the merge source is declared but not emitted; merge-hook failures reject pullOnce. A throwing callback is reported with kind CallbackFailure.

Planned, not implemented

SPEC-0040 specifies a per-database stop-or-discard conflict policy: ConflictPolicy with set_conflict_policy, the reporting operations reconcile_resolving, rollback_resolving and discard, a discarded queue state and an SDK onResolution callback. None of these exist in the current source. Until they ship, rollback and correction conflicts return RollbackConflict with nothing changed; cancel can retain a Cancelled state with unresolved recovery data.

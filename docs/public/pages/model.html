Schema identity

SchemaDefinition has a positive integer version and a map of tables. Each TableDefinition declares columns and relations. The schema is validated on open; a stored schema change requires an authored migration, not simply a higher version number.

Application table, column and relation names must be nonempty, cannot be id, cannot contain a dot and cannot start with __hoya_. Row IDs are separate strings. Internal schema-version fields are not part of public row fields.

Missing is not a replacement value

Declare optionality on the column. replace supplies a complete row, while entity patch supplies only fields to change. Treat missing fields, explicit Null and deletion as separate actions. Command arguments use the separate lossless Json business-value type; Reference and Timestamp cells are not JSON business tags.

Relations are typed navigation

A to-one declaration supplies a Reference foreign key. A Reference type does not promise that the target exists or implement cascading deletion. Keep business referential rules inside your command or application. See relations and validation examples.

Configure first

EntityConfig contains a scope string and table set. The context provider supplies identity and UTC milliseconds. Once configured, ordinary writes to these tables generate entity queue records. Nonconfigured tables keep their ordinary local semantics outside named scopes.

The examples use run, schema, fields and owner from the example support module. run drives this memory fixture; applications with suspending adapters use their async executor. The examples use unwrap() to stop on unexpected failures; an application should handle the typed errors.

Resolve fields, not whole objects

Entity changes carry table, record ID, create/update/delete operation, changed fields, removed fields, a timestamp and per-field timestamps for exactly the changed fields. Core owns field stamps and tombstone rules. patch preserves unsupplied fields, unlike complete-row replace. Equal-time authoritative and local values follow core's explicit resolution rules; an application merge hook cannot change comparison authority.

Configuration is persisted. Reopening the same configuration reinstalls the provider; changing scope/tables is not an arbitrary in-place switch on a populated sync history. Reconfigure is restricted to the reset/pristine conditions in the API. Entity acknowledgements must correlate table, record and write identity.

Platforms

Every platform wraps the same Rust core. No binding reimplements queries, reactivity, the command queue or sync; each one translates calls into the core and events back out. All packages are unreleased local artifacts. This page describes what each binding provides and how far it has been verified; it contains no application code for platforms whose examples are not executed by this documentation.

Browser and Node

See JavaScript and web. In browsers, createWebRuntime() starts the worker that owns protected storage. Open with engine: {kind: 'opfs', name} and a 32-byte encryptionKey. One worker per origin may be active, even across different store names; after the worker retires, a later createWebRuntime() call creates a fresh worker; concurrent replacement opens share it. Existing handles stay closed and requests are not replayed. Replace application-owned workers explicitly. Node and tests initialize the WebAssembly module directly and use memory stores.

Swift

The Swift package (Package.swift) exposes the HoyaDB library and a HoyaDBTesting library. It links the native core through the HoyaNative XCFramework binary target, which must be built first with the package's artifact script (see the Swift README).

  • Database is created with its host options, including onBackgroundError, and opened with openMemory or openProtected. Protected opens take a directory, a store name and a 32-byte key, and report backup exclusion through protection().
  • Queries, observations, commands, sync, entities and errors expose typed Swift DTOs. The Swift quickstart uses its actual methods, including the explicit push/receive/reconcile sequence rather than a JavaScript-style one-shot sync. Errors surface as HoyaError. Observations are Subscription objects, cancelled explicitly or on deinit, and callbacks run on a serial executor (the main queue by default).
  • The commands are command(_:value:context:handler:), which is cancellable through Swift Task cancellation, plus startSync and stopSync. Entity sync uses configureEntities, patch, pullOnce and setMergeHooks. Entity reset has no typed method; it is available only through the advanced execute call.
  • BackgroundError declares five sources, but only observation and sync failures are currently reported.
  • Testing: HoyaDBTesting provides MemoryTesting.open, ManualClock, ManualUptime, ManualTimer and FakeTransport. The macOS slice is x86_64 only.
  • Generated declarations: Swift reference.

Android (Kotlin)

The Kotlin SDK (README) wraps the same native core through JNI. Database is opened with openMemory, which takes a schema, an optional namespace, a memory store and migrations, or with openProtected, which takes an Android Context, a name, a key and the schema, and excludes the store from backup by default. Operations are suspend functions. startSync returns a SyncDriver that you close() to stop it. observe returns an AutoCloseable Subscription, and callbacks run on the database's eventExecutor. Queue states decode into QueueState, and errors are HoyaException values with a kind. The SDK is local and unpublished (dev.hoyadb:hoyadb-android:0.1.0), targets minSdk 24, and is built with the repository's manual tools, not Gradle.

API-0011 requires a per-database Kotlin BackgroundError sink with an onBackgroundError parameter. It is missing from the current source and tracked as DEF-0040. Android reports background sync failures only through startSync's error callback.

Generated declarations: Kotlin reference. The Kotlin quickstart is executed on the emulator; the wider Android SDK gates remain separate.

React Native

@hoyadb/react-native (README, entry) reuses the JavaScript host Database over native iOS and Android modules. openNativeDatabase opens protected native storage from a store name, an encryptionKey and the schema, and excludes it from backup by default. openMemoryDatabase opens a memory store. createNativeRuntime exposes the runtime, and j, query and defineSchema are re-exported. Other host options are forwarded to the Database. Activation and Android build options are described in ACTIVATION.md. Generated declarations: React Native reference.

C ABI

The native boundary (README, hoyadb.h) exports four functions: hoya_v1_abi_version, hoya_v1_open, hoya_v1_call and hoya_v1_validate_open. Every operation exchanges one JSON frame, up to 1 MiB, and invokes exactly one collector with a borrowed reply. Copy its bytes before the collector returns; the caller frees its own copy. Key bytes travel only in the separate binary span of hoya_v1_open; a protected key is 32 bytes and a memory open uses none. No application callback runs inside the C collector. Generated declarations: native reference.

Common rules

  • Keys are caller-owned. The SDKs never persist them or include them in diagnostics.
  • Errors carry a static kind and no payload, key or row value.
  • The stop-or-discard conflict policy (SPEC-0040) is planned and not implemented on any platform.

Application convenience layer

The JavaScript tutorial now uses the plain application API. React Native exports the same builders over its existing native runtime in source; native execution of this addition is not claimed here. Swift and Kotlin retain their existing typed APIs. Kotlin execution is enabled for the documentation example only; wider SDK certification remains held.

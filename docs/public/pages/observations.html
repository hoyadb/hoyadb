Using a binding? Start with its application tutorial. This page teaches the Rust core. Snippets are consecutive parts of one tested program.

Watch local data

The Rust core queues owned notifications. Your host decides when to drain and deliver them. Managed bindings schedule this delivery for you.

The examples use run, schema, fields and owner from the example support module. run drives this memory fixture; applications with suspending adapters use their async executor. The examples use unwrap() to stop on unexpected failures; an application should handle the typed errors.

Read the complete runnable example, including setup and assertions. The verification link beneath each snippet records its execution.

4. Deliver a change

Insert a note, then drain using a monotonic millisecond sample. Match each event's subscription to the token you registered.

The row subscription has an event at this point. The count notification is delayed by its host-driven 16 ms interval; the example checks that it is not delivered early.

5. Schedule a later count drain

The host must arrange the next drain; the core creates no timer. At 16 ms this fixture receives a count of one.

{{example:observations:count}}

6. Stop watching

Release both registrations when their consumers are gone. Removing the last registration releases the shared query group.

{{example:observations:dispose}}

Choose what a change means

Default row observations track membership. Use observe_with_columns when changes to selected cells should also cause delivery. Callback errors do not undo a committed write; refresh_notifications supports explicit refresh. See the binding guide for managed callback delivery.

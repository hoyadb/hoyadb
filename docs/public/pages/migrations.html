Author the transition

A migration names its previous version, complete target schema and ordered steps. Supported steps include AddTable, DropTable, AddColumn, DropColumn, RenameColumn, Backfill and SetRelations. Required new columns need a suitable default for existing rows.

The examples use run, schema, fields and owner from the example support module. run drives this memory fixture; applications with suspending adapters use their async executor. The examples use unwrap() to stop on unexpected failures; an application should handle the typed errors.

Read the complete runnable example, including setup and assertions. The verification link beneath each snippet records its execution.

Preserve the original on failure

The model validates the target and migration plan before applying the atomic schema transition. open_recoverable returns the storage along with an error when open fails; choose it when the caller must retain its adapter. Memory migration tests can reopen the same adapter rather than substituting a new empty one.

Do not edit internal SQLite tables or change the stored schema version yourself. Schema migration is distinct from the planned sync-ledger format converter; no automatic converter is advertised here.

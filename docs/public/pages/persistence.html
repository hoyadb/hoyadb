Supply a key explicitly

SqliteStorage::open_with_options takes a caller-supplied 32-byte EncryptionKey. The no-key convenience open refuses. open_unprotected exists for explicit historical/synthetic fixtures and does not meet the protected contract. There is no automatic plaintext fallback.

The examples use run, schema, fields and owner from the example support module. run drives this memory fixture; applications with suspending adapters use their async executor. The examples use unwrap() to stop on unexpected failures; an application should handle the typed errors.

This fixture creates a unique temporary directory, uses a deliberately disposable constant key, closes and reopens the actual SQLCipher-backed file, rejects a different key and removes only its own directory. Do not copy its fixed key into an application. Acquire production key bytes through your platform's secure key mechanism.

Store lifecycle

The adapter initializes only an empty store and validates known formats. Opening an unknown or damaged store fails; it is not silently reset. A second owner can receive StoreInUse. Close all owners before inspecting, backing up or converting files. Browser OPFS storage has additional worker/pool constraints described under platforms.

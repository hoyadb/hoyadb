Use one owner across your screens

React Native uses the native TurboModule and the JavaScript application layer. Set up the local package and native build using the binding README. There is no published registry package in this checkout. Create one database in your application service and share it; do not open a new owner on every render.

Verification boundary: the shared application flow below executes against the real WASM core in Node. The React Native bootstrap is checked against current exported symbols, but is not compiled or executed: this documentation run does not launch a native app or emulator. It is not native runtime certification.

2. Open the native database

Put the shared file next to the bootstrap in your application service, and call it after the native module is linked. This example uses memory to avoid any key or filesystem setup. For persistence, use openNativeDatabase with an application-managed 32-byte key and the binding's protected-store rules. Never hard-code a production key.

{{example:react-native-bootstrap:open}}

context is supplied by the app and conveys no authorization guarantee. The server authenticates independently. The demo's runTodo closes its owner; in an app, keep the owner alive until application-service shutdown.

4. Observe and dispose

Use the callback to update screen state. Keep the unsubscribe function and dispose it when the screen unmounts. Await ready for installation. An owner shared by other screens stays open.

5. Run a local command

The tracked handler view commits atomically when the handler returns. The backend handler confirms the same named action later. Calls through the outer owner during an admitted handler return Busy. This command edits an existing task; commands creating local: IDs need explicit application mappings.

{{example:react-native:command}}

6. Sync and shut down

sync() performs one push/receive/reconcile/pull pass. startSync() supplies background scheduling. Stop watchers and close only when the service itself shuts down.

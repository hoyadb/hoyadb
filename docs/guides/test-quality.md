# Measuring test quality

Scope: repository verification under [SPEC-0044](../design/spec/SPEC-0044-test-quality-and-mutation.md),
[TC-0048](../design/tests/cases/TC-0048-test-quality-and-mutation.md) and the unchanged
[ADR-0036 coverage policy](../design/decisions/ADR-0036-near-total-code-coverage.md).

## Implementation

[quality.py](../../tests/tooling/quality.py) validates LLVM coverage and
cargo-mutants reports. [coverage.sh](../../tests/tooling/coverage.sh) captures
source hashes and compiler/tool/target/profile/command metadata before running
native workspace tests. Counts and uncovered
locations are retained per component under ignored `target/quality/`, together
with the raw LLVM export. Files without instrumentation remain listed. The runner
requires a target/profile baseline under `tests/tooling/baselines/` (or the
explicit `HOYADB_COVERAGE_BASELINE` path). Comparisons reject different compiler,
LLVM, tool, flags/features, environment, target, profile or scope. The initial
macOS/dev floor comes from its measured counts; it cannot stand in for Linux.
A missing baseline fails with `floor_status: not_established`, preserving counts
and reason. macOS/dev and Linux/release baselines are recorded separately;
`--release` on macOS needs its own measurement and reviewed baseline. Absolute
LLVM/compiler-wrapper paths are part of local comparison identity, so a different
machine layout explicitly needs review rather than silently comparing results.
Sidecar provenance is trusted output of the wrapper, not an LLVM-signed record.
Review the first raw artifact for a new environment before recording its floor;
never automatically replace a floor with the current run to conceal a drop. The
memory crate currently re-exports the core snapshot implementation; its
implementation coverage belongs to core, with no invented memory percentage.

Coverage and mutation snapshots validate the root workspace's four declared
members before collecting their manifests, package-root Rust files (including
`build.rs`), and Rust files under `src`, `tests`, `examples` and `benches`. Shared
`tests/conformance` Rust files and root Cargo/toolchain/mutation configuration
remain inputs. Additions, changes and removals invalidate an in-flight measurement.
Excluded standalone native/web bridges and Cargo `target` output do not belong
to this inventory. A new workspace member requires an explicit inventory update;
separate bridge measurements must identify their own scope. This boundary is
covered by [DEF-0051](../design/defects/DEF-0051-quality-workspace-inventory.md).
Existing recorded baselines and historical reports are not regenerated by this fix.

LLVM file counts include inline unit-test functions in production source files.
Read the raw functions/regions and uncovered source; do not label that aggregate
a production-only line percentage. Stable Rust branch instrumentation remains
unknown, and region coverage is not a substitute. Rustdoc tests run separately;
their execution is not included in this instrumentation.

[mutation.sh](../../tests/tooling/mutation.sh) uses cargo-mutants 27.1.0 with
[the checked-in configuration](../../.cargo/mutants.toml). The default discovers
all native workspace production mutations and runs dependent workspace tests.
It copies the current tree, including uncommitted source, without modifying the
original. On a large checkout this copy and repeated compilation can be costly.
Baseline tests remain enabled. The validator compares the selected inventory
with completed outcomes and rejects survivors, timeouts, missing baselines,
unclassified results, zero caught mutants and stale source. A rejected run keeps
a structured JSON artifact with source hashes, measurement metadata, raw counts,
tool exit status and the error; raw counts on rejected evidence are not validated
scores. The shell preserves the tool's nonzero exit code. Unviable mutations
are reported separately, never as caught. Review raw diffs/logs before judging
a survivor equivalent; no blanket exclusions have been added.

The CI decoder job selects hexadecimal/Unicode/number parsing and the
`json_bounded` integration target alone. Its supervised child asserts exact
numeric and Unicode values/errors and must signal corpus completion within ten
seconds. Zero matching tests, assertion failures and a nonterminating child all
fail; supervisor self-tests cover those cases. Exact malformed-number categories
and underflow results characterize current Rust behavior where API-0006 permits
implementation detail. The original JSON unit tests still run in the full
workspace regression suite. The same 42 mutant names were compared against the initial run: all previous
40 catches remain caught, and the no-progress loop now fails the parent assertion.
The final result is 41 caught, zero missed/timeouts and one unviable, for this
selection only. The supervisor reserves `HOYADB_JSON_TEST_CHILD`; do not set it
when invoking the suite. Its expected failed/empty child summaries are nested
inside a passing parent self-test; use parent/Cargo status for suite results.

The initial unit-test-only decoder experiment found 40 caught mutations, one
unviable mutation and one non-progressing-loop timeout. Its strict gate was red;
raw evidence remains in `target/quality/mutation-initial/`. No timeout allowlist,
source exclusion or production rewrite was added. The full 2,921-candidate native
inventory was listed, not executed. The proposed unbounded scheduled full job
was removed after the independent review showed its repeated full-suite cost.
Full discovery/default workspace testing remain available locally; broader
mutation selections need an explicit budget and complete outcome validation.
They are not represented by the focused CI result.
The pinned Node host job runs the complete client/testing suites and React Native
host tests. Its `javascript-wasm` dependency builds the ordinary bridge with
wasm-bindgen 0.2.129 and supplies `crates/hoyadb-web/pkg/` as a CI artifact, so the
application tests exercise real WASM on a clean checkout. This does not certify
real-browser or mobile execution. Local builds use the same
[contributor prerequisites](../../CONTRIBUTING.md#start-here).

[javascript-coverage.sh](../../tests/tooling/javascript-coverage.sh) uses Node's
built-in test coverage for the client and testing package. Its include patterns
omit test code and generated WASM glue. Only imported JavaScript is instrumented:
the worker entry and real browser/native/mobile paths are not certified by Node.
The real WASM tests require an ordinary asset rebuilt from the current sources.

## Rules

Preserve assertions and public contracts. Test returned values, errors, rollback
and persisted state rather than successful method invocation. Use shared adapter
conformance cases for database behavior, and host doubles only for host policy.
Keep a regression test and defect record for every confirmed fix. The browser
bootstrap recovery regression is [DEF-0041](../design/defects/DEF-0041-browser-bootstrap-retry.md).

Reports must identify their scope and source. Missing instrumentation and
unexecuted targets remain unknown. A selected mutation score is not a workspace
score; a cargo-mutants timeout remains a failed experiment requiring investigation.
A supervised parser child that exceeds its bounded test deadline is killed and
reaped, and its parent assertion fails; that is an actual test failure, with
its log retained, rather than relabelling a tool timeout. Inline tests,
generated glue and unimported files must not silently inflate a product claim.
No numerical coverage floor is invented before a baseline exists. Raising
coverage does not prove all documented behavior or all public names are correct.

## Required checks

Run from the repository root with the pinned Rust toolchain. Tool installs below
are development tools, placed under ignored `target/`; they are not runtime
dependencies. Both tools are pinned and installed with their lockfiles.
The validator uses Python 3.11 or newer (`tomllib`). Tool references:
[cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov),
[cargo-mutants](https://mutants.rs/) and
[Node coverage reporters](https://nodejs.org/download/release/v22.18.0/docs/api/test.html#coverage-reporters).

```sh
cargo install cargo-llvm-cov --version 0.9.1 --locked --root target/quality-tools
cargo install cargo-mutants --version 27.1.0 --locked --root target/quality-tools
export PATH="$PWD/target/quality-tools/bin:$PATH"
rustup component add --toolchain 1.98.1 llvm-tools-preview
python3 -m unittest discover -s tests/tooling -p 'test_quality.py'
sh tests/tooling/coverage.sh
CARGO_PROFILE_RELEASE_OVERFLOW_CHECKS=true sh tests/tooling/mutation.sh --profile release
```

On the audited macOS host, LLVM 22.1.8 also matches rustc's LLVM; use the explicit
`LLVM_COV` and `LLVM_PROFDATA` paths to that installed toolchain if the rustup
component is absent. Do not silently change the compiler or enable bootstrap.

For a focused decoder investigation matching CI:

```sh
sh tests/tooling/mutation.sh \
  --file crates/hoyadb-core/src/command/json.rs \
  --re 'hex_quad|unicode|digits|number' \
  --test-workspace=false --test-package hoyadb-core \
  -- --test json_bounded
```

Run one mutation invocation at a time: reports have fixed paths. Keep the shell
scripts unchanged while they run. Move an earlier result directory aside before
starting a new investigation if its raw evidence should be retained.

```sh
sh crates/hoyadb-web/build.sh
sh tests/tooling/javascript-coverage.sh
cargo test --workspace --offline --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --offline --locked -- -D warnings
python3 tools/traceability/trace_check.py docs/design
python3 tools/traceability/rtm_gen.py docs/design --check
```

## Update this page when

Change the scope inventory, tool pins, CI selection or documented commands when
the corresponding scripts or workspace change. A new memory implementation must
replace the strictly validated re-export exception with its own measurement.
Track platform/branch measurement and floor enforcement explicitly when added;
do not infer them from successful host tests.
